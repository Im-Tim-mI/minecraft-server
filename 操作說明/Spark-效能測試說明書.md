# ============================================
# 3. 查看 TPS
# ============================================

## 指令

```
/spark tps
```

## 輸出範例

```
TPS from last 5s, 10s, 1m, 5m, 15m:
  20.0, 20.0, 19.98, 19.95, 19.92

Tick durations (min/med/95%ile/max ms) from last 10s, 1m:
  8.2/12.5/25.3/45.2;  5.1/15.2/35.4/89.3

CPU usage from last 10s, 1m, 15m:
  25%, 28%, 30%  (system)
  18%, 22%, 25%  (process)
```

## 數值解讀

### TPS（每秒 Tick 數）

| TPS 範圍    | 狀態      | 說明                  |
|------------|----------|----------------------|
| 20.0       | ✅ 完美   | 伺服器運行順暢        |
| 18.0-19.9  | ✅ 良好   | 輕微延遲，可接受      |
| 15.0-17.9  | ⚠️ 警告   | 明顯卡頓，需要優化    |
| 10.0-14.9  | ❌ 嚴重   | 嚴重卡頓，必須處理    |
| <10.0      | ❌ 崩潰   | 幾乎無法遊玩          |

### MSPT（每 Tick 毫秒數）

| MSPT 範圍   | 狀態      | 說明                  |
|------------|----------|----------------------|
| <50ms      | ✅ 正常   | 有足夠的處理餘裕      |
| 50-70ms    | ⚠️ 警告   | 接近上限              |
| >70ms      | ❌ 超標   | 無法維持 20 TPS       |

### 計算公式

```
TPS = 1000ms / MSPT

MSPT 50ms  → TPS = 1000/50 = 20（滿分）
MSPT 100ms → TPS = 1000/100 = 10（一半）
```

# ============================================
# 5. 效能分析（Profiler）
# ============================================

## 基本用法

### 步驟 1：開始分析

```
/spark profiler start
```

### 步驟 2：等待 1-3 分鐘

讓伺服器正常運行，玩家正常遊玩，收集足夠的數據。

### 步驟 3：停止並查看報告

```
/spark profiler stop
```

會生成一個網頁連結，例如：
```
https://spark.lucko.me/QHcNkCl4Ao
```

## 進階選項

### 設定分析時間（自動停止）

```
/spark profiler start --timeout 120
```
120 秒後自動停止並生成報告。

### 只分析特定執行緒

```
/spark profiler start --thread Server thread
```
只分析主執行緒（最常用）。

### 只分析 Tick 過長的時候

```
/spark profiler start --only-ticks-over 50
```
只記錄耗時超過 50ms 的 tick。

### 查看進行中的分析

```
/spark profiler open
```

### 取消分析

```
/spark profiler cancel
```

## 報告解讀

打開報告網頁後：

### 主要區域

1. **TPS/MSPT 圖表**：時間軸上的效能變化
2. **CPU 使用率**：處理器負載
3. **記憶體使用量**：RAM 使用情況
4. **All View**：詳細的呼叫樹

### 如何找問題

1. 點擊展開 `Server thread 100%`
2. 找到佔用百分比最高的項目
3. 繼續展開找到具體原因

### 常見問題項目

| 看到這個                    | 表示問題是              |
|----------------------------|------------------------|
| `Chunk loading`            | 區塊載入太慢            |
| `Entity tick`              | 實體太多                |
| `Block entity tick`        | 方塊實體太多（漏斗等）   |
| `Plugin: XXX`              | 某插件效能差            |
| `Pathfinding`              | 生物尋路計算太多        |
| `Village POI`              | 村民工作站檢測太頻繁    |


# ============================================
# 6. 記憶體分析
# ============================================

## 記憶體摘要

```
/spark heapsummary
```

查看各類物件佔用的記憶體。

## 記憶體快照

```
/spark heapdump
```

匯出完整的記憶體快照（用於深入分析）。

⚠️ 警告：heapdump 檔案很大，可能暫時卡頓伺服器。

## 垃圾回收監控

```
/spark gc
```

查看 GC 狀態。

```
/spark gcmonitor
```

開始監控 GC 活動，再次輸入關閉。


# ============================================
# 7. Tick 監控
# ============================================

## 開啟監控

```
/spark tickmonitor
```

會實時顯示每個 tick 的耗時：

```
Tick #1523 - 15.2ms
Tick #1524 - 12.8ms
Tick #1525 - 85.3ms  ← 超過 50ms 會標紅
Tick #1526 - 18.5ms
```

## 關閉監控

```
/spark tickmonitor
```

再次輸入即可關閉。

## 設定閾值

```
/spark tickmonitor --threshold 100
```

只顯示超過 100ms 的 tick。

# ============================================
# 9. 報告解讀範例
# ============================================

## 範例 1：村民問題

```
▼ Server thread - 100%
  ▼ tick - 85%
    ▼ tickEntities - 60%
      ▼ Villager.tick - 45%
        ▼ Brain.tick - 30%
          ▼ acquirePoi - 25%
```

**診斷**：村民的 AI 計算（尋找工作站）佔用 25%

**解決**：
- 減少村民數量
- 設定 `tick-inactive-villagers: false`

---

## 範例 2：漏斗問題

```
▼ Server thread - 100%
  ▼ tick - 85%
    ▼ tickBlockEntities - 40%
      ▼ HopperBlockEntity.tick - 35%
```

**診斷**：漏斗方塊實體佔用 35%

**解決**：
- 減少漏斗數量
- 調整 `ticks-per.hopper-transfer: 16`

---

## 範例 3：區塊載入問題

```
▼ Server thread - 100%
  ▼ tick - 85%
    ▼ ChunkMap - 30%
      ▼ processUnloads - 20%
```

**診斷**：區塊載入/卸載佔用大量資源

**解決**：
- 降低視野距離
- 設定 `delay-chunk-unloads-by: 10s`

---

## 範例 4：插件問題

```
▼ Server thread - 100%
  ▼ tick - 85%
    ▼ Plugin: SomePlugin - 40%
      ▼ onTick - 35%
```

**診斷**：某插件的 onTick 方法效能差

**解決**：
- 更新或移除該插件
- 聯繫插件作者


# ============================================
# 10. 常見問題診斷
# ============================================

## 診斷流程

```
1. /spark tps              ← 確認 TPS 低
        ↓
2. /spark health           ← 查看整體狀態
        ↓
3. /spark profiler start   ← 開始分析
        ↓
4. 等待 1-2 分鐘
        ↓
5. /spark profiler stop    ← 生成報告
        ↓
6. 打開報告，找出問題來源
        ↓
7. 根據問題進行優化
        ↓
8. 重啟伺服器
        ↓
9. /spark tps              ← 確認改善
```

## 常見問題速查

| 症狀                  | 可能原因              | 診斷指令              |
|----------------------|----------------------|----------------------|
| TPS 低               | 實體/區塊/插件        | /spark profiler      |
| 記憶體高             | 物件太多/記憶體洩漏   | /spark heapsummary   |
| 間歇性卡頓           | GC 暫停              | /spark gcmonitor     |
| 特定時間卡頓         | 定時任務/自動存檔     | /spark tickmonitor   |

## 優化優先級

1. **村民 AI** - 最常見的效能殺手
2. **實體數量** - 動物、怪物過多
3. **漏斗** - 大量漏斗會拖慢伺服器
4. **區塊載入** - 視野距離太高
5. **插件** - 效能差的插件
